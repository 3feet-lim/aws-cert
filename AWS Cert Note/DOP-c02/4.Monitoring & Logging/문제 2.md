

한 회사가 규제 컴플라이언스 요구사항을 충족하기 위해 AWS Key Management Service(AWS KMS) 키와 수동 키 교체(manual key rotation)를 사용한다. 보안팀은 어떤 키든 90일이 지나도록 교체되지 않았을 때 알림을 받고자 한다.

이를 달성할 솔루션은?

**A.** 키가 90일보다 오래되었을 때 Amazon SNS 주제로 게시하도록 AWS KMS를 구성한다.

**B.** AWS Lambda 함수를 실행하는 Amazon EventBridge 이벤트를 구성하여, Lambda가 AWS Trusted Advisor API를 호출하고 Amazon SNS 주제로 게시하도록 한다.

**C.** 키가 90일보다 오래되었을 때 Amazon SNS 주제로 게시하는 AWS Config 커스텀 규칙을 개발한다.

**D.** 키가 90일보다 오래되었을 때 Amazon SNS 주제로 게시하도록 AWS Security Hub를 구성한다.



# 해설

정답: C

해설:

핵심은 KMS 키가 마지막 교체 후 90일을 초과했는지를 지속적으로 평가하고, 초과 시 보안팀에 알리는 것이다. AWS Config는 리소스의 구성 상태를 상시 평가하는 서비스이고, 원하는 조건(키 나이 90일 초과)을 판정하는 로직은 커스텀 규칙(Lambda 기반)으로 구현할 수 있다. 규칙이 비준수(NON_COMPLIANT)를 감지하면 EventBridge/SNS로 연동해 알림을 보낼 수 있어 요구사항을 정확히 충족한다. 수동 교체 이력을 기준으로 나이를 계산해야 하므로 관리형 규칙보다 커스텀 규칙이 적합하다.

오답 이유:

A. AWS KMS에는 "키가 90일 넘었을 때 SNS로 게시"하는 기본 기능이 없다. KMS 자체가 키 나이를 감시해 알림을 발행하지 않으므로 존재하지 않는 기능을 전제한 함정이다.

B. Trusted Advisor는 비용·성능·보안·내결함성 등에 대한 모범 사례 점검 서비스로, "수동 교체된 KMS 키가 90일을 초과했는지"를 판정하는 체크를 제공하지 않는다. Trusted Advisor API를 호출해도 이 조건에 해당하는 데이터가 없어 요구를 충족하지 못한다.

D. Security Hub는 여러 보안 findings를 집계·표시하는 서비스이지, 이 커스텀 조건(수동 교체 90일 경과)을 직접 평가해 SNS로 알리는 도구가 아니다. Security Hub의 KMS 관련 표준 컨트롤은 대개 "자동 키 교체 활성화 여부"를 보는 것이라 수동 교체 시나리오와 맞지 않는다. 이 조건을 판정하려면 결국 Config 커스텀 규칙이 필요하다.
