
한 회사가 단일 AWS 리전에서 수백 개의 Amazon EC2 인스턴스를 실행하는 단일 AWS 계정을 보유하고 있다. 이 계정에서는 매시간 새 EC2 인스턴스가 시작되고 종료된다. 또한 이 계정에는 일주일 넘게 실행 중인 기존 EC2 인스턴스도 포함되어 있다.

회사의 보안 정책은 실행 중인 모든 EC2 인스턴스가 EC2 인스턴스 프로파일을 사용하도록 요구한다. EC2 인스턴스에 인스턴스 프로파일이 연결되어 있지 않다면, 그 인스턴스는 IAM 권한이 전혀 할당되지 않은 기본 인스턴스 프로파일을 사용해야 한다.

DevOps 엔지니어가 계정을 검토하다 인스턴스 프로파일 없이 실행 중인 EC2 인스턴스를 발견했다. 검토 중에 새 EC2 인스턴스들도 인스턴스 프로파일 없이 시작되고 있음을 관찰했다.

리전 내 **모든 기존 및 향후** EC2 인스턴스에 인스턴스 프로파일이 연결되도록 보장하는 솔루션은?

**A.** EC2 RunInstances API 호출에 반응하는 Amazon EventBridge 규칙을 구성한다. 이 규칙이 AWS Lambda 함수를 호출해 EC2 인스턴스에 기본 인스턴스 프로파일을 연결하도록 구성한다.

**B.** `ec2-instance-profile-attached` AWS Config 관리형 규칙을 구성 변경(configuration changes) 트리거 유형으로 구성한다. AWS Systems Manager Automation 런북을 호출해 EC2 인스턴스에 기본 인스턴스 프로파일을 연결하는 자동 교정 작업을 구성한다.

**C.** EC2 StartInstances API 호출에 반응하는 Amazon EventBridge 규칙을 구성한다. 이 규칙이 AWS Systems Manager Automation 런북을 호출해 EC2 인스턴스에 기본 인스턴스 프로파일을 연결하도록 구성한다.

**D.** `iam-role-managed-policy-check` AWS Config 관리형 규칙을 구성 변경 트리거 유형으로 구성한다. AWS Lambda 함수를 호출해 EC2 인스턴스에 기본 인스턴스 프로파일을 연결하는 자동 교정 작업을 구성한다.


# 해설

정답: B

해설:

핵심 요구는 "기존 인스턴스와 향후 인스턴스 모두"에 인스턴스 프로파일을 보장하는 것이다. 이벤트 기반 방식은 이벤트가 발생하는 순간(신규 생성 등)에만 반응하므로 이미 실행 중인 기존 인스턴스를 커버하지 못한다. 반면 AWS Config는 리소스 상태를 상시 평가하므로 기존·신규를 모두 잡아낸다. AWS는 정확히 이 용도의 관리형 규칙 `ec2-instance-profile-attached`를 제공하며, 이 규칙이 프로파일 없는 인스턴스를 비준수로 표시하면 SSM Automation 런북을 자동 교정 작업으로 연결해 기본 인스턴스 프로파일을 자동으로 붙인다. 관리형 규칙이라 커스텀 로직도 불필요해 요구를 정확히 충족한다.

오답 이유:

A. EventBridge가 RunInstances(인스턴스 시작) API에만 반응하므로 **신규로 시작되는 인스턴스만** 교정한다. 이미 일주일 넘게 실행 중인 기존 인스턴스는 RunInstances 이벤트를 새로 발생시키지 않으므로 전혀 처리되지 않아 "기존 인스턴스 포함" 요구를 위반한다.

C. StartInstances는 중지된 인스턴스를 다시 시작할 때 발생하는 이벤트로, 신규 생성(RunInstances)이나 계속 실행 중인 기존 인스턴스를 커버하지 못한다. 이벤트 범위가 더 좁아 오답이다.

D. 자동 교정을 붙이는 구조는 B와 유사하지만 규칙 선택이 틀렸다. `iam-role-managed-policy-check`는 IAM 역할에 특정 관리형 정책이 붙어 있는지를 검사하는 규칙이지, EC2 인스턴스에 인스턴스 프로파일이 연결됐는지를 평가하는 규칙이 아니다. 평가 대상 자체가 어긋난다.
