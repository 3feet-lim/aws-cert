한 회사가 Application Load Balancer(ALB)로 HTTP API 호출을 하는 모바일 애플리케이션을 운영하고 있다. ALB는 요청을 AWS Lambda 함수로 라우팅한다. 특정 사용자 그룹이 테스트 중인 버전을 포함해, 여러 버전의 애플리케이션이 동시에 사용되고 있다. 애플리케이션 버전은 모든 API 요청에 함께 전송되는 user-agent 헤더에 정의되어 있다.

최근 일련의 API 변경 이후, 회사는 애플리케이션에서 문제를 관찰했다. 회사는 **사용 중인 각 애플리케이션 버전별로, 각 API 오퍼레이션에 대해 응답 코드별 메트릭**을 수집해야 한다. DevOps 엔지니어는 이미 Lambda 함수를 수정하여 API 오퍼레이션 이름, user-agent 헤더의 버전 정보, 응답 코드를 추출하도록 했다.

필요한 메트릭을 수집하기 위해 DevOps 엔지니어가 추가로 취해야 할 조치는?

**A.** Lambda 함수가 API 오퍼레이션 이름, 응답 코드, 버전 번호를 로그 라인으로 CloudWatch Logs 로그 그룹에 기록하도록 수정한다. 각 API 오퍼레이션 이름마다 메트릭을 증가시키는 CloudWatch Logs 메트릭 필터를 구성하고, 응답 코드와 애플리케이션 버전을 메트릭의 디멘션으로 지정한다.

**B.** Lambda 함수가 위 정보를 로그 라인으로 CloudWatch Logs 로그 그룹에 기록하도록 수정한다. CloudWatch Logs Insights 쿼리를 구성하여 로그 라인으로부터 CloudWatch 메트릭을 채우고, 응답 코드와 버전을 디멘션으로 지정한다.

**C.** ALB 액세스 로그를 CloudWatch Logs 로그 그룹에 기록하도록 구성한다. Lambda 함수가 API 오퍼레이션 이름·응답 코드·버전 번호를 응답 메타데이터로 ALB에 반환하도록 수정한다. 메트릭 필터를 구성하고 응답 코드와 버전을 디멘션으로 지정한다.

**D.** Lambda 함수에 AWS X-Ray 통합을 구성한다. Lambda가 API 오퍼레이션 이름·응답 코드·버전 번호를 담은 X-Ray 서브세그먼트를 생성하도록 수정한다. X-Ray insights를 구성하여 API 오퍼레이션별 집계 메트릭을 추출하고 CloudWatch에 게시하며, 응답 코드와 버전을 디멘션으로 지정한다.


# 해설

정답: A

해설:

핵심은 "각 애플리케이션 버전별로, 각 API 오퍼레이션에 대해 응답 코드별 메트릭"을 수집하는 것이다. 즉 필요한 것은 (오퍼레이션 이름 = 메트릭) × (응답 코드, 버전 = 디멘션) 구조의 CloudWatch 커스텀 메트릭이다. Lambda가 이미 세 정보를 추출하도록 수정돼 있으므로, 이를 구조화된 로그 라인으로 CloudWatch Logs에 기록하고 **메트릭 필터(metric filter)**로 로그에서 메트릭을 뽑아내는 방식이 정석이다. 메트릭 필터는 로그 패턴을 매칭할 때마다 메트릭 값을 증가시키고, 응답 코드와 버전을 디멘션으로 지정할 수 있어 요구사항과 정확히 맞는다.

오답 이유:

B. CloudWatch Logs Insights는 로그를 대화형으로 질의·분석하는 **쿼리 도구**이지, 로그로부터 지속적으로 CloudWatch 메트릭을 자동 생성·게시하는 기능이 아니다. "Insights 쿼리로 메트릭을 populate한다"는 설명 자체가 실제 동작하지 않는 함정이다. 로그에서 상시 메트릭을 뽑는 것은 메트릭 필터(또는 EMF)의 역할이다.

C. ALB 액세스 로그는 S3로 전달되며 CloudWatch Logs로 직접 쓸 수 없고, 무엇보다 user-agent 헤더에서 파싱해야 하는 애플리케이션 버전이나 API 오퍼레이션 이름 같은 커스텀 정보를 담지 못한다. 또한 "Lambda가 응답 메타데이터로 ALB에 반환"해도 그 값이 액세스 로그나 메트릭으로 이어지지 않아 요구사항을 충족하지 못한다.

D. X-Ray는 분산 추적(지연·병목 분석)용이지 버전·응답 코드별 카운트 메트릭 집계 도구가 아니다. "X-Ray insights가 서브세그먼트를 집계해 오퍼레이션별 메트릭을 CloudWatch에 게시한다"는 동작은 존재하지 않으며(X-Ray Insights는 이상 징후 탐지 기능), 커스텀 디멘션 메트릭을 만드는 데는 과도하고 부적합하다.
