
한 회사가 애플리케이션 릴리스를 자동화하기 위해 AWS CodePipeline 파이프라인을 사용한다. 일반적인 파이프라인은 빌드, 테스트, 배포의 세 단계로 구성된다. 회사는 각 단계의 스크립트를 실행하기 위해 별도의 AWS CodeBuild 프로젝트를 사용해 왔다. 그러나 이제 파이프라인의 배포 단계를 AWS CodeDeploy로 처리하고자 한다.

회사는 애플리케이션을 RPM 패키지로 패키징했으며, 이를 Amazon EC2 인스턴스 플릿에 배포해야 한다. EC2 인스턴스들은 EC2 Auto Scaling 그룹에 속해 있으며 공통 AMI에서 시작된다.

요구사항을 충족하기 위해 DevOps 엔지니어가 수행해야 할 단계의 조합은? (2개 선택)

**A.** CodeDeploy 에이전트가 설치된 공통 AMI의 새 버전을 만든다. EC2 인스턴스의 IAM 역할을 업데이트하여 CodeDeploy에 대한 접근을 허용한다.

**B.** CodeDeploy 에이전트가 설치된 공통 AMI의 새 버전을 만든다. 애플리케이션 배포 스크립트를 포함하고 CodeDeploy에 대한 접근을 부여하는 AppSpec 파일을 만든다.

**C.** CodeDeploy에서 애플리케이션을 만든다. 인플레이스(in-place) 배포 유형을 구성한다. Auto Scaling 그룹을 배포 대상으로 지정한다. CodePipeline 파이프라인에 EC2 Image Builder로 새 AMI를 만드는 단계를 추가한다. 새로 만든 AMI를 배포하도록 CodeDeploy를 구성한다.

**D.** CodeDeploy에서 애플리케이션을 만든다. 인플레이스 배포 유형을 구성한다. Auto Scaling 그룹을 배포 대상으로 지정한다. CodeDeploy 액션을 사용해 애플리케이션을 배포하도록 CodePipeline 파이프라인을 업데이트한다.

**E.** CodeDeploy에서 애플리케이션을 만든다. 인플레이스 배포 유형을 구성한다. 공통 AMI에서 시작된 EC2 인스턴스들을 배포 대상으로 지정한다. CodeDeploy 액션을 사용해 애플리케이션을 배포하도록 CodePipeline 파이프라인을 업데이트한다.



# 해설

정답: A, D

해설:

CodeDeploy로 EC2에 배포하려면 두 축이 필요하다. 하나는 대상 인스턴스가 CodeDeploy와 통신할 수 있어야 하고(A), 다른 하나는 파이프라인과 CodeDeploy 애플리케이션이 올바르게 구성돼야 한다(D).

A — CodeDeploy는 각 EC2 인스턴스에 설치된 **CodeDeploy 에이전트**를 통해 배포를 수행하므로, 공통 AMI에 에이전트를 심어 새 버전을 만들면 그 AMI로 뜨는 모든 인스턴스가 배포 대상이 될 수 있다. 또한 인스턴스가 배포 번들(S3의 아티팩트 등)에 접근하려면 EC2 인스턴스 프로파일의 IAM 역할에 해당 권한이 있어야 한다.

D — CodeDeploy에서 애플리케이션과 배포 그룹을 만들고 인플레이스 배포 유형을 구성하되, 대상을 **Auto Scaling 그룹**으로 지정하는 것이 핵심이다. ASG를 대상으로 지정하면 스케일 아웃으로 새로 추가되는 인스턴스에도 최신 리비전이 자동 배포되어 플릿 전체 일관성이 유지된다. 마지막으로 CodePipeline의 배포 단계를 CodeDeploy 액션으로 교체한다.

오답 이유:

B. AMI에 에이전트를 설치하는 전반부는 옳지만, AppSpec 파일은 AMI에 굽는 것이 아니라 배포되는 애플리케이션 리비전(번들)의 루트에 포함되는 파일이다. 또한 AppSpec은 라이프사이클 훅과 파일 매핑을 정의할 뿐 "CodeDeploy에 대한 접근 권한을 부여"하지 않는다(권한은 IAM 역할의 몫). 개념이 뒤섞인 함정이다.

C. Auto Scaling 그룹 대상·인플레이스 구성은 맞지만, 이 시나리오는 RPM 패키지를 실행 중인 인스턴스에 배포하는 것이지 매번 새 AMI를 굽는 방식이 아니다. EC2 Image Builder로 새 AMI를 만들어 배포한다는 단계는 불필요하게 복잡하고 CodeDeploy의 애플리케이션 리비전 배포 모델과도 맞지 않는다.

E. 대상을 "공통 AMI에서 시작된 개별 EC2 인스턴스들"로 지정하는 점이 D와 갈리는 지점이자 오답 사유다. Auto Scaling 그룹 환경에서 개별 인스턴스나 태그로 대상을 고정하면, 이후 스케일 아웃으로 새로 뜨는 인스턴스에는 애플리케이션이 배포되지 않아 플릿이 불일치하게 된다. ASG 자체를 대상으로 삼아야(D) 신규 인스턴스까지 자동 커버된다.
