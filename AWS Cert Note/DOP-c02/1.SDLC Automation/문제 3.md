
한 DevOps 엔지니어가 AWS Lambda 함수를 사용하는 서버리스 애플리케이션을 위한 지속적 배포(CD) 파이프라인을 구축하고 있다. 회사는 실패한 배포가 고객에게 미치는 영향을 줄이고자 한다. 또한 문제를 모니터링하고자 한다.

이 요구사항을 충족하는 배포 단계 구성은?

**A.** AWS Serverless Application Model(AWS SAM) 템플릿을 사용해 서버리스 애플리케이션을 정의한다. AWS CodeDeploy를 사용해 `Canary10Percent15Minutes` 배포 기본 설정 유형(Deployment Preference Type)으로 Lambda 함수를 배포한다. Amazon CloudWatch 경보를 사용해 함수의 상태를 모니터링한다.

**B.** AWS CloudFormation을 사용해 새 스택 업데이트를 게시하고, 모든 리소스에 Amazon CloudWatch 경보를 포함한다. 개발자가 CloudFormation 변경 집합(change set)을 검증·승인하도록 AWS CodePipeline 승인 액션을 설정한다.

**C.** AWS CloudFormation을 사용해 스택 업데이트마다 새 버전을 게시하고, 모든 리소스에 Amazon CloudWatch 경보를 포함한다. `AWS::Lambda::Alias` 리소스의 `RoutingConfig` 속성을 사용해 스택 업데이트 중 트래픽 라우팅을 업데이트한다.

**D.** AWS CodeBuild를 사용해 테스트용 샘플 이벤트 페이로드를 Lambda 함수에 추가한다. 함수의 새 버전을 게시하고 Amazon CloudWatch 경보를 포함한다. 프로덕션 별칭(alias)이 새 버전을 가리키도록 업데이트한다. 경보가 ALARM 상태일 때 롤백이 발생하도록 구성한다.
