
한 회사가 AWS CodeDeploy를 도입하여 Apache 웹서버가 포함된 Java-Apache Tomcat 애플리케이션의 배포를 자동화하려 한다. 개발팀은 개념 증명(PoC)으로 시작해 개발자 환경용 배포 그룹을 만들고 애플리케이션 내에서 기능 테스트를 수행했다. 완료 후, 팀은 스테이징과 프로덕션용 추가 배포 그룹을 만들 예정이다.

현재 로그 레벨은 Apache 설정 내에 구성되어 있는데, 팀은 배포가 일어날 때 이 설정을 동적으로 변경하고 싶어 한다. 그래서 각 그룹마다 별도의 애플리케이션 리비전을 두지 않고도, 배포 그룹에 따라 서로 다른 로그 레벨 구성을 설정할 수 있기를 원한다.

이 요구사항을 **최소한의 관리 오버헤드**로, 그리고 **배포 그룹마다 다른 스크립트 버전을 요구하지 않으면서** 충족하려면 어떻게 해야 하는가?

**A.** 배포 그룹에 따라 EC2 인스턴스에 태그를 지정한다. 그런 다음 메타데이터 서비스와 EC2 API를 호출해 인스턴스가 어느 배포 그룹에 속하는지 식별하는 스크립트를 애플리케이션 리비전에 넣는다. 이 정보로 로그 레벨 설정을 구성한다. 이 스크립트를 appspec.yml의 AfterInstall 라이프사이클 훅으로 참조한다.

**B.** CodeDeploy 환경 변수 DEPLOYMENT_GROUP_NAME을 사용해 인스턴스가 어느 배포 그룹에 속하는지 식별하는 스크립트를 만든다. 이 정보로 로그 레벨 설정을 구성한다. 이 스크립트를 appspec.yml의 BeforeInstall 라이프사이클 훅으로 참조한다.

**C.** 환경마다 CodeDeploy 커스텀 환경 변수를 만든다. 그런 다음 이 환경 변수를 확인해 인스턴스가 어느 배포 그룹에 속하는지 식별하는 스크립트를 애플리케이션 리비전에 넣는다. 이 정보로 로그 레벨 설정을 구성한다. 이 스크립트를 appspec.yml의 ValidateService 라이프사이클 훅으로 참조한다.

**D.** CodeDeploy 환경 변수 DEPLOYMENT_GROUP_ID를 사용해 인스턴스가 어느 배포 그룹에 속하는지 식별하고 로그 레벨 설정을 구성하는 스크립트를 만든다. 이 스크립트를 appspec.yml의 Install 라이프사이클 훅으로 참조한다.





# 해설

정답: B

해설:

핵심 요구는 "최소 관리 오버헤드"와 "배포 그룹마다 다른 스크립트 버전을 두지 않는 것"이다. CodeDeploy는 배포 중 실행되는 스크립트에 자동으로 환경 변수를 주입하는데, 그중 `DEPLOYMENT_GROUP_NAME`은 현재 배포 대상 그룹의 이름을 담고 있다. 단일 스크립트가 이 변수를 읽어 분기(예: developer → DEBUG, production → WARN)하면, 모든 배포 그룹이 동일한 하나의 스크립트·하나의 애플리케이션 리비전을 공유하면서도 그룹별로 다른 로그 레벨을 적용할 수 있다. 추가 태깅·API 호출·커스텀 변수 생성이 필요 없어 오버헤드가 가장 낮다. 또한 로그 레벨은 애플리케이션 파일 설치 전에 세팅하는 것이 자연스러우므로 `BeforeInstall` 훅이 적절하다.

오답 이유:

A. 기술적으로 동작은 하지만 오버헤드가 크다. 인스턴스 태깅을 별도로 관리해야 하고, EC2 메타데이터 서비스와 EC2 API를 호출하려면 추가 IAM 권한과 API 로직이 필요하다. CodeDeploy가 `DEPLOYMENT_GROUP_NAME`을 이미 제공하는데 굳이 우회하는 셈이라 "최소 관리 오버헤드" 기준에서 B에 밀린다.

C. CodeDeploy에는 사용자가 배포 그룹별로 임의의 "커스텀 환경 변수"를 정의해 주입하는 기능이 없다. 존재하지 않는 기능을 전제로 한 함정이다. 또한 로그 레벨 구성을 배포 검증 단계인 `ValidateService`에 두는 것도 부적절하다.

D. `DEPLOYMENT_GROUP_ID`도 실제 존재하는 CodeDeploy 환경 변수지만, ID는 사람이 읽기 어려운 식별자라 스크립트에서 그룹을 구분해 로그 레벨을 매핑하기에 이름(`DEPLOYMENT_GROUP_NAME`)보다 불편하고 유지보수성이 떨어진다. 게다가 `Install`은 CodeDeploy가 파일을 복사하는 예약된 단계로, 사용자 스크립트를 이 훅에 직접 지정할 수 없다. 훅 지정 자체가 잘못됐다.
